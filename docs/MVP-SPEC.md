# Finance Product Agent — MVP 0.1

## 目标与边界

为个人财务数字化产品经理提供本地工作台，将财务访谈、澄清、业务流程、财务规则、PRD、可点击原型、UAT 与变更影响连成一个可追溯闭环。仓库只包含合成演示数据。不上线、不接 ERP、不生成会计/税法结论、不自动审批，不调用云模型。

## 验收标准

1. 使用 Python 3.11+ 标准库启动，浏览器只连接 127.0.0.1；无需依赖安装、账户或 API 密钥。
2. 需求支持来源、目标、责任人、成功指标及逐项澄清；空答案阻止基线通过。
3. 流程明确角色、输入、动作、输出、后续节点；规则记录依据、适用期间、币种、金额口径、舍入、职责分离与异常处理，金额使用 Decimal。
4. PRD 和页面、UAT 均引用稳定 ID；非法引用、孤立验收、重复 ID、无覆盖需求均报错。
5. 导出 PRD Markdown、流程 Mermaid、UAT CSV、追踪矩阵及安全静态 HTML 原型，不加载第三方资源。
6. SQLite 追加版本：编辑必须填写操作者与原因，使用版本检查防止覆盖；保存差异、哈希与传递影响范围；任何新版本使旧签署失效。UAT 通过必须有证据和执行人。
7. 验收门禁要求澄清完成、规则合规字段完整、需求均有 PRD/流程/规则/页面/UAT 覆盖、UAT 全部通过且有当前版本人工签署。门禁只是准备状态，不执行部署。
8. 模板草案与 AI 输出明确标为待复核，不伪造财务政策。本地模型需启动参数和逐次按钮触发；仅允许 synthetic/sanitized 分类，连接失败显示真实错误。
9. 测试覆盖金额边界、非法输入与引用、版本冲突、签署失效、数据外传开关、HTML 注入与 HTTP 写保护；提供可复现命令和测试输出。

## 增量切片

- M1：数据校验、金额规则求值、版本与门禁，先测试再实现。
- M2：本地网页编辑、导出与可点击页面、合成端到端演示。
- M3：复用上游提示词的本地 AI 草案、文档、安全审查与交付。

## 技术取舍

选择下游轻量衍生模块，而不是完整改名打包 Electron。实际复制并在运行时使用上游 BRD/PRD/BP 定义上下文，保留固定 commit 与 LICENSE。重写财务领域核心，不移植带云提供商/遥测的运行时，也不宣称 Python 工作台等同上游功能。后续需要完整桌面编辑器时再将领域服务接回 Electron；当前没有维护两个前端。
